Stage 2

Product Intent And Principles

Turn the relaunch idea into explicit product principles, success criteria, and non-goals before content modeling begins.

Reader Goal

After 2 minutes, understand the relaunch thesis and what the implementation plan must protect.

Back to plan

Unit 01 - Relaunch thesis

Define “adventures are living wikis” for players, authors, admins, and the LLM. Clarify that the wiki is the canonical adventure source and Convex syncs live sessions.

Verification

User can approve or revise the thesis in plain language.

Unit 02 - Success criteria

Define authoring, gameplay, LLM quality, admin, migration, validation, and rollout success criteria for the final implementation plan.

Verification

Every later architecture option can be scored against these criteria.

Unit 03 - Non-goals

Record that v1 is not unrestricted markdown chaos, not old editor preservation, not JSON compatibility beyond Myr template migration, and not a full public CMS unless explicitly added.

Verification

Non-goals prevent scope creep in later stages.

Unit 04 - Decision framework

Create a scoring model for storage, frontmatter strictness, validation severity, AI editing autonomy, and realtime behavior.

Verification

Stage 8 can cite this framework when choosing implementation milestones.
