Unit 01 - Folder patterns

Compare single-file, folder wiki, and hybrid models. Preferred direction is folder wiki with adventure.md as the root manifest and required frontmatter per publishable page.

Verification

Decision table explains why the chosen S3 layout supports authoring, links, validation, and retrieval.

Unit 02 - Frontmatter contract

Define required keys such as id, type, title, settingId, adventureId, start, visibility, version, and optional tags.

Verification

Every required key has a runtime consumer or validation purpose.

Unit 03 - Markdown conventions

Define optional but recommended sections for Intro, GM Notes, Secrets, NPCs, Locations, Transitions, Checks, Rewards, Map Notes, and Author Notes.

Verification

Conventions remain human-writable and do not recreate rigid JSON.

Unit 04 - Myr template model

Design how current Myr adventure plan templates become wiki folders, including page naming, migrated encounters, NPC refs, maps, and premade characters.

Verification

At least one representative Myr template can be sketched end-to-end.
