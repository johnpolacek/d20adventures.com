Admin Wiki Authoring Rebuild

Replace the visible legacy AdventurePlan admin flow with a per-adventure wiki authoring surface where chat is primary, key-field editing is secondary, and canonical source writes go to S3.

Decisions

  • Default adventure improvement is the first scope; creating new adventures remains deferred.
  • Admin chat applies changes directly to canonical wiki source instead of creating draft review queues.
  • S3 content/settings/{settingId}/... is the canonical admin source; repo-local content is a bootstrap/dev fallback.
  • Direct editing is limited to key fields for markdown and character JSON, not raw source editing.
  • Every chat, key-field, or restore write creates an S3-backed authoring revision that can restore the full draft or selected file.

Implementation Shape

  • Add complete source-tree loading, revision restore, and change-set writes for wiki adventures.
  • Compile gameplay runtime from S3 source when available, falling back to migrated repo-local content.
  • Replace the admin dashboard entry with /admin/wiki-adventures and per-adventure editor routes.
  • Keep validation visible after each chat or key-field save.

Validation

Expected validation includes the focused admin-authoring check, migrated adventure bridge checks, TypeScript, build, and route smoke where practical.
