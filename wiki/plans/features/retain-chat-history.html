Feature plan

Retain Chat History

Make per-adventure game chat durable, reloadable, access-controlled, and useful across sessions without losing the current lightweight in-game chat workflow.

Summary

Status

Unit 01 - access and pagination contract

Audit chat reads/writes and implement authenticated paginated history loading.
Blockers
None; retention duration is assumed indefinite until a policy decision says otherwise.
Validation
Convex query coverage, route/action auth checks, UI reload test, and regression check for live chat updates.

Reader Goal

After 2 minutes, the reader can implement retained chat history without weakening adventure access controls or conflicting with the wiki-adventure migration.

Target Data Flow

In scope

Scope

Load older chat messages for an adventure after refresh, return visits, or modal reopen; preserve live updates; keep unread tracking; and enforce the same owner/player access used by adventure turns.

Out

Non-goals

No cross-adventure global inbox, moderation console, full-text search, message editing, reactions, attachments, or AI summarization in this pass.

Assumption

Retention Policy

Retain messages indefinitely with no soft-delete or archival job for v1. Add retention controls later if privacy, cost, or moderation requirements demand them.

Execution Units

Unit 01 - Access and Pagination Contract

Define and implement a server-authenticated history read path that returns messages before a cursor or timestamp. Cap page size, keep ordering stable, and document whether the UI uses Convex query, server action, or route handler for pagination.

Verification

Add or update tests around unauthorized adventure access, participant access, page-size limits, and chronological ordering. If automated Convex tests are impractical, record a manual verification script with seeded messages.

Unit 02 - Reloadable Chat UI

Update GameChat so opening chat loads the latest messages, exposes a load-older affordance when more history exists, preserves scroll position when prepending older rows, and keeps new live messages appended without duplication.

Verification

Manually verify modal open, page refresh, reopen after close, load older, unread badge reset, and live delivery from a second session or browser context.

Unit 03 - Migration Alignment and Cleanup

Align the retained-chat implementation with the wiki-adventure migration's live Adventure model. Keep chat as Convex live session state, not S3 authored content. Remove any redundant fetch path introduced during implementation and update source briefs only if the runtime contract changes.

Verification

Run pnpm exec tsc --noEmit and a focused manual chat-history regression. Run pnpm check only if the known Biome config issue is resolved or record that blocker.

Risks

Duplicated SSE connections can overcount unseen messages, cursor pagination can skip messages with identical timestamps, and any direct Convex client query path would need careful authorization review.

Implementation Notes

Prefer a cursor based on message document id plus created time if Convex APIs make it practical. Otherwise use bounded timestamp pagination with deterministic secondary ordering documented in code comments or tests.
